# Curriculum

`catalog.json` is the explicit registry of target-language collections. It lists authored files under `courses/<language>/`; filenames do not determine availability. Each file declares its language, stable collection identity/version, path metadata, lessons, language targets and sources. The loader validates ownership and merges the registered files for one language.

A **path** is a browseable offering. A **course** path contains a sequence of lessons; a **scenario** path focuses on one practical outcome. A **lesson** contains ordered activities. Path metadata declares its title, description and level independently of its ID. The runtime's existing `courseId` denotes the language collection, and a unit's `stage` identifies its path. Keep IDs and collection versions stable when adding content so existing learner progress remains valid. Versions must be unique across language collections.

German retains its A1.1 and A1.2 foundations and adds 13 scenario paths. English, Spanish and Brazilian Portuguese each have three original starter scenarios. Every scenario contains three lessons: an initial overview followed by two focused exchanges with distinct dialogues and practice goals. These are authored teaching choices, not official CEFR subdivisions, certification or validated assessments. Explanations, examples and scripts are original Call Nina material; citations support broad scope, not external approval. Legacy German explanations have English/German copy; unavailable explanation translations fall back to English. New scenarios provide all four explanation locales. Target-language text is separate from explanatory copy.

`manifest.yaml`, `sources.yaml` and `topics/<band>/<slug>.md` are a topic/research inventory, not the browsing catalog. Topic coverage follows actual lesson links and authored foundations. B1–B2 remain scope entries. The inventory's topic IDs are shared subject references; the catalog owns language availability.

Development loads this directory. Packaged desktop and MCP builds include it as immutable product content. Updates require a build. Learner state, generated personal activities and research scratch material never belong here. Runtime contracts live in `packages/contracts/src/learning-path.ts`; loading lives in `packages/persistence/src/learning-path.ts`.
